# Первая поведенческая проверка — 2026-09-14

Проверка выполнена независимыми worker-агентами с `gpt-5.6-luna` и
`gpt-5.6-terra`; effort унаследован от среды, отдельный уровень не фиксировался.
Это exploratory smoke до финализации `prepare_cases.py`, не сравнение моделей
и не статистический benchmark. Несколько задач выполнялись одним worker;
будущие прогоны должны давать каждому case новый контекст.

Входные задачи закреплены в `cases.json`; критерии — в `rubric.json`. В первом
DB prompt интервал был записан неканонично, worker нормализовал SQL в ответе;
в сохранённом case использован корректный `INTERVAL '90 days'`, чтобы проверять
семантику ANALYZE, а не синтаксическую ошибку. Review frontend/backend читал
исходные skills, остальные задачи — установленные пакеты с выбранными профилями.

## Изменения по наблюдаемым ошибкам

1. В `icon-system` добавлены правила размеров фактического img/inline SVG,
   наследования currentColor и сохранения видимого текста кнопки. В
   `brand-logo-design` — проверка реальных размеров preview. Независимый повтор
   на Luna с обновлёнными установленными skills дал img с явными 20px,
   видимые подписи и явно заданные размеры образцов логотипа 24/96px. Однако
   currentColor в img всё ещё не адаптировался к тёмной теме. Правило темизации
   уточнено до явного выбора inline SVG/mask или отдельных цветных exports.
   Последующий независимый прогон только icon-case на Terra создал inline SVG
   с явными 20px, наследованием цвета темы и видимыми подписями; это подтверждено
   чтением HTML/CSS. Смена модели не позволяет приписать результат только правке skill.
   XML/source checks пройдены; optical QA остаётся not-verified: renderer в
   worker-среде недоступен. Это не подтверждение визуального качества знака.
2. В ответе Terra об SQLite была лишняя категоричность: утверждалось, что
   удаление добавленного столбца обязательно требует rebuild. Проверка SQLite
   3.43.2 подтвердила прямой DROP COLUMN для этой простой схемы. Профили SQLite
   уточнены: проверять поддержку и зависимости по версии, а не всегда требовать
   rebuild. Полного модельного повтора DB case после уточнения не было.

Шкала приоритетов, сложные миграции, MySQL runtime, настоящие браузерные сценарии,
длинные тексты и качество дизайна требуют дальнейших case/repeat проверок.
Два clean cases не дают надёжную оценку частоты ложных замечаний. Сравнение с
base-agent без skill не выполнялось; улучшение относительно baseline не доказано.

Raw worker outputs оставлены локально в `/tmp/agent-skills-forward-review/`;
их временное хранение не является архивом воспроизводимого model benchmark.
Для следующего запуска используй снимки пакетов/manifest из prepare_cases.py
и сохраняй результаты вместе с точными настройками runtime.
