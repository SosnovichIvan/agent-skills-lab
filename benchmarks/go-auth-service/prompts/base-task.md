# Единое задание benchmark

Создай с нуля production-oriented HTTP-сервис аутентификации на Go.

Функциональные требования:

- `POST /register` регистрирует пользователя по email и паролю;
- `POST /login` проверяет учётные данные и возвращает access token;
- сервис создаёт подписанные токены и валидирует подпись, алгоритм, issuer и
  срок действия;
- middleware извлекает Bearer token и выполняет авторизацию;
- защищённый `GET /me` возвращает идентификатор и email текущего пользователя;
- email нормализуется и проверяется, пароль валидируется;
- повторная регистрация одного email запрещена;
- хранилище пользователей in-memory и безопасно для конкурентного доступа;
- секрет, issuer, адрес и TTL читаются из environment; без безопасного секрета
  сервис не должен запускаться;
- сервер имеет разумные timeouts и graceful shutdown;
- JSON-ответы и ошибки имеют единообразный формат.

Технические ограничения:

- используй только стандартную библиотеку Go, без внешних зависимостей;
- access token должен иметь JWT-compatible формат HS256;
- пароль храни как соль и результат итеративного HMAC-SHA256 KDF, сравнивай в
  constant time; открытый пароль не хранить;
- раздели transport, service, repository, token и password concerns по
  понятным пакетам или файлам;
- создай `go.mod` и весь необходимый исходный код;
- не создавай тестовые файлы и не пиши тесты;
- выполни `gofmt`; используй `go test ./...` только как проверку компиляции
  пакетов без добавления тестов.

Работай автономно до полного готового к компиляции результата. Не используй
web и не задавай уточняющих вопросов. Не выполняй commit, push или публикацию.
