# Технические тексты

Читайте для README, tutorial, API guide, troubleshooting и release notes.

Выбери цель: tutorial ведёт к результату, how-to решает задачу, reference даёт
точный контракт, explanation объясняет причины. Не смешивай всё в одну инструкцию.

Команды согласуй с версией и конфигурацией проекта. Раздели prerequisite,
действие и наблюдаемую проверку успеха; не вставляй секреты в примеры.
Сохраняй рабочие пути и placeholders. Не утверждай, что пример исполнялся,
если только проверил синтаксис или прочитал документацию.

Для API укажи семантику обязательных/необязательных полей, ошибок и повторов,
если это нужно читателю. Для release notes опиши изменение поведения и действие
пользователя при несовместимости, а не перечень внутренних файлов.

Проверь ссылки и команды в доступной среде; сетевые/разрушительные примеры
не запускай автоматически только ради проверки текста.
