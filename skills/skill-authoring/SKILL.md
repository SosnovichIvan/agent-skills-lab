# Оформление навыков

Создавай каждый навык как самостоятельную папку в `skills/`. Единственная
обязательная точка входа — `SKILL.md`. Пользовательский skill должен
устанавливаться и выполнять своё назначение без других skills.

## Структура

Используй имя папки, совпадающее с именем навыка: строчные латинские буквы,
цифры и дефисы. Выбирай короткое действие или предметную область, например
`skill-authoring`.

```text
skills/<skill-name>/
├── SKILL.md
├── agents/             # только если нужны UI-метаданные
│   └── openai.yaml
├── prompts/            # только для готовых пользовательских/runtime-промптов
├── references/
│   ├── *.md            # references полностью связанного skill
│   ├── common/         # обязательная часть модульного skill
│   └── options/        # выбираемые языки/framework-профили
├── scripts/            # только для повторяемой детерминированной логики
└── assets/             # только для файлов, используемых в результате
```

Не создавай пустые каталоги «на будущее». Для skill, который всегда
устанавливается целиком, допускаются файлы непосредственно в `references/`.
Добавляй `references/common/`, когда материал обязателен в каждом варианте
модульного skill. Добавляй `references/options/`, когда язык, framework или
редкий сценарий выбирается при установке. Каждый option зарегистрируй у
родительского skill в `skills/catalog.json`; reference не является
самостоятельным skill и не может устанавливаться отдельно.
Из `SKILL.md` должна быть понятная ссылка и условие, когда reference читать.
Готовые для копирования или внедрения промпты храни только в `prompts/`, а
исполняемый код — только в `scripts/`; не смешивай эти назначения.

## SKILL.md

Начинай файл с YAML frontmatter с полями `name` и `description`.

- `name` совпадает с именем папки.
- `description` кратко объясняет результат, условия применения и при
  необходимости границу с похожими задачами.
- Основной текст содержит только решения, ограничения и порядок действий,
  которые действительно меняют поведение агента.
- Не дублируй общие системные инструкции, учебники и очевидные действия.
- Для условных, подробных или редких сценариев используй прогрессивное
  раскрытие: короткое правило в `SKILL.md`, подробности — в `references/`.

## Добавление или обновление

1. Проверь, нет ли уже навыка с тем же назначением; расширяй существующий,
   если это сохраняет одну понятную точку входа.
2. Создай или обнови нужные файлы в папке навыка.
3. Добавь skill, его обязательные references и options в `skills/catalog.json`.
   Для framework dependency используй `requires`, чтобы установщик добавлял
   базовый профиль автоматически. Если категории выбираются отдельно, объяви
   `selection_groups` с `min`/`max`; пользовательский файл допускай только
   явным `allow_custom_file` у принадлежащей skill группы.
   Не используй `requires_skills` для объединения пользовательских skills или
   запуска одного skill из другого. Композицию, порядок шагов и контракт передачи
   результата описывай во внешнем prompt задачи. Поле `requires_skills` оставляй
   только для неразделимой технической runtime-зависимости, без которой skill в
   принципе не способен работать; такая зависимость не должна быть обычным
   функциональным skill.
4. Добавь или обнови строку в `skills/README.md`: идентификатор навыка,
   относительная ссылка на `SKILL.md`, название правила и практическое
   назначение.
5. Проверь структуру командой
   `quick_validate.py <путь-к-папке-навыка>` из инструментария
   `skill-creator`.
6. Выполни smoke-test через `python3 install.py ... --yes` и проверь уже
   собранную папку skill. В ней не должно быть невыбранных options.

Сохраняй автоматическое обнаружение навыка по умолчанию. Отключай его в
`agents/openai.yaml` только по явному требованию пользователя. Не используй
`allow_implicit_invocation` как механизм обязательного запуска: обязательность
задаётся project execution policy и, если агент поддерживает, runtime guard.
